==============================================================================
 UPDATE: DEPARTMENT DATABASE TABS (replaces the old single DeptDB table)
==============================================================================
 1. TABS under Department database: the dept admin creates tabs users
    switch between, from templates Client Info, Meetings, Employee Info,
    Billing, Accounts, or a blank custom tab, with starter columns the
    admin can customise per tab. Filter and sorting sit on top of the tabs.
 2. SEE / EDIT / SHARE: every user in the same department can see every
    row in a tab, but only the owner can edit it. The owner may share a
    row with another department or a specific user, setting View only or
    Can edit. Edit history is shown on the row page.
 3. DELEGATE: the dept admin can choose a user to do everything a dept
    admin can do in the Department Database (Department database >
    Delegates), including creating tabs and editing every row.
 4. MEETINGS move to the Meetings tab (not connected to Client Info):
    its rows carry client name, address, contact number, date and time.
    Notifications now come 7, 3 and 1 days before and on the morning of
    the meeting, with the same dept-admin wording as before.
 5. UPGRADE: old DeptDB columns/rows become a "General" tab, so nothing
    is lost. ./backup.sh, unzip over the old folder, docker compose up
    -d --build. Details: README.txt section 22.

==============================================================================
 UPDATE: DEPT DATABASE MEETINGS + ATTACHMENT COLUMNS
==============================================================================
 1. MEETING NOTIFICATIONS in the Department Database: a date column with a
    time is a meeting schedule. The row owner gets "You have a meeting at
    <date time>" and every dept admin gets "<USER> has a meeting at
    <date time>", the day before the meeting and again on the morning of
    the meeting (after REMINDER_HOUR, default 7 AM). Each message once only.
 2. ATTACHMENT COLUMNS in the Department Database: new "Attachment (file)"
    column type, so a user can add a file to a row, with Download on the
    row page. Portal admin can give access to which dept admin can create
    such a column: Admin > DeptDB attachment access, or Users > Edit user.
    Dept admins without that access cannot create attachment columns.
 UPGRADE: ./backup.sh, unzip over the old folder, docker compose up -d --build.
 Details: README.txt section 21.

==============================================================================
 UPDATE: INVOICES, RANDOM PUBLIC QR CODES (HRC-#####), WATERMARK, TWO LOGOS
==============================================================================
 1. NEW tab "Invoices": dept-admin templates (Billing, Admin Expense Voucher,
    Conveyance Bill, custom Purchase Request), employee invoices with live
    totals, Draft -> Issued -> Paid / Void, PDF and print. Dept admin sees
    every invoice in their own department; the portal admin does not make
    templates. Changes to a template apply to new invoices only.
 2. INVOICE PDF: top row left HRC logo + company + single-line address, right
    second logo in the top right corner (optional). Invoice type is centred
    ON TOP OF THE TABLE, table moved lower. Currency beside every amount.
    Watermark OFF by default; template can turn it on and type the text
    (ISSUED, PAID, DRAFT, VOID, or custom). If OFF, no watermark is shown.
 3. PUBLIC QR CODE SYSTEM CHANGED FOR ALL PUBLIC QRs: HRC- + random 5-digit
    code (for example HRC-48392), not sequential HRC-0, HRC-1 and not INV-12.
    Existing record QRs were given a random code on upgrade. New scan link
    for an invoice gives a new random code, so the old printed QR stops.
 4. LOGIN-ONLY CODE SEARCH: you must be logged in to search a code in the
    search bar, view it and download its PDF. Without login, no view.
 5. SHARING: dept admin can share a template with another dept admin, who
    can Use it in their own department (a copy; original unchanged, revocable).
    Separately, a dept admin can share their department's invoices, view-only,
    with another dept admin (revocable, optional expiry).
 UPGRADE: ./backup.sh, unzip over the old folder, docker compose up -d --build.
 Details: README.txt section 20.

==============================================================================
 UPDATE: SHARING WITH ONE PERSON, EDIT / VIEW ONLY, REPLACE ATTACHMENT
==============================================================================
 1. The owner can share a record with a WHOLE DEPARTMENT or with ONE CHOSEN PERSON
    (any department), and for each choose "Can edit" or "View only".
 2. View-only people can read the record, download files and write suggestions,
    but cannot edit, upload, replace or remove files.
 3. REPLACE button next to every attachment (for everybody who can edit). The old
    file is deleted, the new one is virus-checked, and the change is written in the
    Edit history like every other change. The owner gets a bell message.
 4. Sharing changes are in the history too. Bulk share has the same choices.
 Existing shares stay "Can edit". Details: README.txt section 18.
 UPGRADE: ./backup.sh, unzip over the old folder, docker compose up -d --build.

==============================================================================
 WHAT IS NEW IN THIS VERSION  -  overview
==============================================================================
 Your data is safe: the database upgrades itself on the first start. An upgrade from
 the previous version was tested with real records, repairs, logins and activity log.

 UPGRADE STEPS (server that already runs the portal)
   1. cd inventory-portal      ./backup.sh        (always take a backup first)
   2. Unzip the new version over the old folder (or into a new folder).
      Keep your own PORTAL_PORT and TZ lines in .env (the new .env has new lines).
   3. docker compose up -d --build
   4. Log in as before. Never run  docker compose down -v

 1. PUBLIC QR CODE
    * Switch per record: the owner chooses which fields anyone may see, creates the QR,
      turns it off, or makes a new code (old printed QR stops working).
    * One QR for many records: tick records in a list > Public QR.
    * Safe by design: random unguessable link, only chosen fields, no history/files,
      rate limit, not indexed by search engines, view counter, manage page for all links.
 2. MOBILE VIEW  Menu button, tables become cards, one-column forms, big buttons,
    sticky bulk bar. Buttons and icons are now aligned the same everywhere.
 3. HAND OVER RECORDS  New owner must accept; history shows it; admin can hand over at once.
 4. BULK ACTIONS  Tick many records: share, public QR, labels, Excel, PDF, CSV, delete.
 5. NOTIFICATIONS  Bell with counter: shares, handovers, requests, comments, suggestions,
    virus alerts, daily reminder summary.
 6. REQUESTS WITH APPROVAL  New item / repair / other. Department admin or admin decides.
 7. COMMENTS AND SUGGESTIONS on every record (separate from the edit history).
 8. EXCEL AND PDF  Formatted exports of lists, selected records, one record, and a
    Reports page (records, reminders, open repairs, summary, activity log).
 9. SAVED FILTERS AND SORTING  Filter by any column, sort by any column (numbers sort
    as numbers), save the view with a name.
10. LOOK  Auto / Light / Dark mode, saved per user.
11. HTTPS  Optional Caddy front door (built-in certificate or your own).
12. DEPARTMENT ADMIN  Sees every record of the department, writes suggestions, decides
    requests, runs department reports. Cannot edit others' records.
13. VIEW OTHER DEPARTMENTS  The admin allows a user to view chosen departments and write
    suggestions. No editing. Users still add and edit their own records.
14. PASSWORD RE-ENTRY for dangerous admin actions (valid 5 minutes).
15. BETTER LOGIN PROTECTION  Lock per username and per computer (IP), saved attempts,
    strong password rule (letters + numbers), sessions list, admin can end a session.
16. SHORTER IDLE TIMEOUT  Logout after 30 minutes without activity.
17. VIRUS SCANNING of attachments with ClamAV (optional container, fail-safe).
18. IP ADDRESS in the admin activity log (also for failed logins) and in reports.

 THINGS TO KNOW
   * A public QR can be opened by anyone who can reach the server (the office network or
     VPN), so tick only fields that are fine to show to everyone.
   * PDF files print English and European letters; other letters print as ? (Excel keeps them).
   * Tested here: all 200+ automated checks of every feature (the virus scanner with a
     simulated ClamAV), the upgrade from the previous version, phone and dark-mode
     screens. NOT tested here (no Docker available): the Caddy HTTPS container and the
     real ClamAV container. If one does not start, send the output of
     docker compose logs caddy   or   docker compose logs clamav
   * The Android app needs the phone to trust the certificate if you turn on HTTPS
     with the built-in certificate.
